# Write the topic files
Create the eight topic files under `docs/agents/specs/engine-shutdown/`. Each one starts with a back-link to the hub (`[Engine Graceful Shutdown](../engine-shutdown.md)`) and carries the content of #1004 / #1008 listed below:

- **`semantics.md`** — the `shutdown({ timeoutMs })` → `Promise<boolean>` API and its meaning (`true` drained, `false` timed out); the `#draining` state; `keepAlive` stays an immutable constructor option; during drain the loop keeps running but skips `promoteReadyJobs()`, `allocator.allocate()` and the idle-timeout tracking; idle detection by polling `workersRegistry.hasBusyWorker()` each tick (reusing `sleepMs`); no cancellation of in-flight `perform()`; `#enqueued` / `#retryQueue` / `#failed` untouched and not lost; cooling-down jobs in `#failed` not promoted during drain (intended, not a bug); the "Expected" guarantees from #1004; the design-decisions table from #1004 (where it lives, return value, `keepAlive` mutability, loop exit, `start()` on timeout, retry promotion, timeout with work in flight).
- **`loop-exit.md`** — why clearing `keepAlive` is not enough (`#continueAllocating()` = `hasJob() || hasBusyWorker()`, and `hasJob()` stays true with a backlog); the explicit drain branch in `#shouldContinue()` with the code snippet from #1004; only busy workers keep the loop alive while draining; `#drainTimedOut` ends the loop so `start()` resolves even when `shutdown()` returns `false`; `start()` can resolve with `perform()` calls still running; the existing `!#stopped` guard is unchanged.
- **`edge-cases.md`** — the pinned edge cases: before `start()`; after the loop exited (idempotent); called twice (joins the first call, same result, timeout not reset); while `#stopped` is set; `timeoutMs` omitted or `0` (no wait, resolve with `!hasBusyWorker()`, no implicit infinite wait); `shutdown()` must return a defined boolean even if `start()` was rejected or never called.
- **`idle-hook.md`** — the optional `onWorkerIdle` refinement (owned by #1010): fourth `Worker` constructor attribute next to `jobRegistry`, `workersRegistry`, `loggerFactory`; forwarded by `WorkerFactory#build()`; invoked in `Worker#perform()`'s `finally` right after `setIdle`; no payload (a wake-up, not a state transfer); safe no-op when unset, including `WorkersRegistryInstance`'s default factory (built without a `loggerFactory`); `Engine` re-checks `hasBusyWorker()` on wake-up; motivation: drain latency below `sleepMs`.
- **`testing.md`** — the Jasmine cases from #1004 under `deku-swarm/spec/` (mirroring `lib/`): the nine `Engine` cases (owned by #1009) and the two `Worker` cases (owned by #1010, only if the hook ships).
- **`out-of-scope.md`** — flush mode (and why: it changes the "pending jobs untouched" contract; a possible future opt-in `shutdown({ flush: true })`); `drain` / `drained` events (`Engine` never self-emits; hosts emit around `await shutdown()`); switching Navi's `EngineController` to `shutdown()` (adoption belongs to consumers or a separate issue); cooperative cancellation of `Job.perform()` (needs a signature change).
- **`versioning.md`** — additive, non-breaking change, so `deku-swarm` gets a **minor** bump `1.12.0` → `1.13.0`, done in #1009 with `bump_version.sh` (link `docs/agents/release.md`); #1010 adds no further bump if it lands before that version is released, otherwise it takes its own minor bump.
- **`open-questions.md`** — items left for later sub-issues, each tagged with its owner: drain-observation granularity with `sleepMs` polling and whether it is acceptable without the hook (#1009); how `Engine` wires `onWorkerIdle` into `WorkerFactory` and wakes the loop on it (#1010); exact README/guide placement of the new API and its caveats (`start()` resolving with work in flight, frozen retry promotion) (#1011). State that each sub-issue updates this file as it resolves its items.
